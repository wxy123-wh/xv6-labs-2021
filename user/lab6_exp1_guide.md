# 实验一：动态分区分配实现（小白友好版）

## 快速运行
- 编译：`cd /root/os-lab/xv6-labs-2021/user && gcc -std=c11 -Wall -Wextra -O2 lab6_exp1.c -o lab6_exp1`
- 执行：`./lab6_exp1`
- 程序会依次用 First Fit、Best Fit、Worst Fit 处理请求 `{50,30,20,40,60,10,25}`（单位 KB），并给出摘要与释放合并示例。

## 核心数据结构
- `free_area_t`：空闲分区节点，记录起始地址、大小、下一节点。
- `memory_manager_t`：管理器，持有空闲链表、总容量，以及分配/释放计数。
- 空闲链表按起始地址升序，便于后续释放时检测重叠和合并。

## 代码如何工作
1. **初始化**（`init_memory_manager`）
   - 创建一个覆盖全部内存的空闲节点 `[addr=0, size=total_size]`。
   - 分配/释放计数清零。
2. **First Fit / Best Fit / Worst Fit 分配**
   - 在空闲链表里找符合 `size` 的分区：
     - First Fit：遇到第一个够大的就用。
     - Best Fit：选最小的可用分区，减少碎片。
     - Worst Fit：选最大的可用分区，保留大块空间。
   - 如果分区大小正好相等，直接摘链表并释放节点；否则从分区头部切出 `size`，调整起始地址和剩余大小。
   - 找不到则返回 `-1` 表示失败。
3. **释放与合并**（`release_memory`）
   - 检查地址合法性（不越界、不与已有空闲分区重叠）。
   - 将新空闲块按地址插入链表。
   - 若与前/后分区相邻则合并，避免产生额外碎片。
4. **指标统计与演示**
   - `run_sequence` 运行给定算法和请求序列，统计成功次数、空闲分区数、平均碎片大小。
   - `show_release_demo` 先分配三块，再按不同顺序释放，展示合并效果。

## 运行输出怎么读
- 每个算法部分显示每次请求的分配结果和最终空闲链表。
- “Summary” 摘要展示成功率和碎片指标，便于横向比较。
- “Release & merge demo” 展示释放后空闲链表如何一步步合并回完整空间。
